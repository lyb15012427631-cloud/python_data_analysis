## 第1学时：让程序做判断

导入：“同样输入一个金额，为什么有的提示超预算，有的不提示？上周只会计算，今天让程序根据结果选一条路。”
先问：input得到的"120"是什么？"120"+"30"与120+30分别是什么？答不出时回到类型转换，不急于引入分支。
用代码02把比较结果直接打印为True/False；强调bool是新的类型，比较不会直接输出业务结论。
代码03先预测再运行：120对100超预算，100对100不超预算。板书`条件 → True执行if → False执行else`，指出冒号和4空格缩进。
代码04演示-1、0、99、100、499、500。提问：“500为什么进入else？如果先判断amount >= 100，后面再elif amount >= 500，会发生什么？”让学生看到顺序造成的逻辑错误。
代码05只讲and、or、not的含义，不展开复杂嵌套。跟练“100≤金额<500”。
检查：不看答案判断100的档位，解释=和==区别。题1函数外的分支部分可先写，第三学时再封装。

## 第2学时：让程序处理一组数据

导入：“如果有五笔支出，难道要写五遍print？如果是五万笔呢？”先展示列表，再循环。
代码06：方括号、逗号、位置0和-1、切片不含右端；append把元素放到原列表末尾。不要一次加入字典和二维结构。
代码07让学生在纸上列出每一轮expense取值。强调for后变量接收的是值，不是自动编号。

## 第3学时：什么时候停，怎样重复使用规则

代码11：每轮开始判断余额是否小于目标；指出使条件最终不成立的余额更新语句。目标350而每次100，四次后400恰好说明“至少”含义。先预测轮数，再运行。
避免现场运行故意缺少更新的无限循环；用文字展示错误，并说明Jupyter中断按钮。完成题4。
过渡：“不同数据都要检查预算，复制十遍代码容易改漏。把规则放到函数里。”代码12依次解释def、函数名、形参、冒号、函数体、调用和实参。
代码13必须展示print与return差异：屏幕看到了20，不代表变量接到了20。没有return时返回None。函数内部局部变量不要当成外部可直接读取的变量。
代码14将第一学时的分档封装成函数，多个边界值循环调用；学生完成题1最终版本。
检查：让学生写一个返回两数之和的函数，接收结果后再乘2。只print不能通过这一检查。

## 第4学时：用基础函数完成一份小分析

代码15对应问法：有几笔→len，一共多少→sum，最小最大→min/max，平均每笔→sum/len。round用于显示，abs表示差额大小；业务方向仍要靠带符号差额或条件表达。
代码16说明sorted返回新列表；排名和时间变化是不同问题，不能把排序后的序列当原时间顺序。
代码17先看正常均值，再传空列表，解释为什么不能除以0。None代表没有结果，不代表金额0。
代码18先只展示业务要求，不急于给全代码。画出流程：原始列表→筛选→检查有效笔数→统计→预算判断→一句结论。学生用题7的另一组数据独立做，再讲评参考答案。
结束提问：“均值分母为何是5而不是6？负数为什么没有计入？0是否应该计入？”目标是让学生解释处理口径，而不是只得到400。

## 常见错误与排查

| 现象 | 检查方法 |
|---|---|
| SyntaxError或IndentationError | 查英文冒号、=与==、分支缩进；不要复制全角标点 |
| "120"与100不能比较 | 检查input结果类型，先float或int转换；本周只要求合法数字输入 |
| 统计结果只有最后一笔 | 查total=0是否被放进循环内部 |
| 每次循环都输出一个“总额” | 区分中间观察输出和循环结束后的最终输出 |
| range少/多一次 | 先列出起始值与停止值，停止值不包含 |
| while不停止 | 查循环内是否更新条件相关变量，先中断内核再修正 |
| 函数调用结果是None | 检查是否只有print、是否所有需要的路径都有return |
| NameError或旧结果 | 确认已运行定义单元；重新从头执行，检查内核与运行顺序 |
| 空列表求均值或最值报错 | 先len判断，不把没有数据解释为0 |
| sorted后原列表没变 | 它返回新列表，需接收或打印返回结果 |
